# FDEX v1.1.21

本版本修复纯文本聊天错误显示附件状态、记忆辅助请求争抢主 AI 生成线路，以及流式异常后重复长时间重试的问题，并让员工可以直接读取本机项目记录事实。

## 聊天状态与故障恢复

- 纯文本消息显示“正在连接 AI…”，只有真实存在附件时才显示“正在准备 N 个附件并连接 AI…”。
- 纯文本会把服务端历史附件型进度文案归一化为文本请求文案。
- `Software caused connection abort`、供应商 5xx/不可用等真实失败不再触发第二个最长数分钟的非流式请求。
- 非流式兼容回退仅保留给 SSE 正文/尾标记缺失等协议兼容故障，并继续复用同一 request_id。

## MemPalace / Letta 韧性

- MemPalace 语义/Qdrant 召回采用短预算；语义服务不可用时直接从 SQLite verbatim drawers 做员工 ACL 约束的本地词法召回。
- Memory Provider Proxy v2 优先使用供应商原生 OpenAI-compatible `/embeddings`，短时间不可用时使用本地 Unicode text-hash vector。
- 移除生成式“FDEX 语义索引规范化 API”回退，不再为了 embedding 额外调用聊天模型。
- Letta request-time recall 直接读取 agent 的 `human` core-memory block，不再生成 `[RECALL_ONLY]` 请求。
- Letta 写入直接更新 `human` core-memory block，不再生成 `[MEMORY_UPDATE]` 请求。
- Letta 结构化条目明确区分 `USER_STATEMENT` 与 `ASSISTANT_RESULT`，避免把历史 AI 回复自动当成用户事实；MemPalace 继续保存逐字原始历史。

## 项目记录

- 当用户询问历史项目、项目记录、项目统计/汇总等内容时，客户端直接加入本机项目事实：标题、状态、需求完整度、创建/更新时间、备注数量、资料数量、报告数量和项目描述。
- 项目统计不再完全依赖聊天记忆或向量召回。
