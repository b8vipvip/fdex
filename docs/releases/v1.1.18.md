# FDEX v1.1.18

本版本修复 Android 客户端在图片、文档等附件任务中，AI 服务端已经成功生成答案，但聊天页面仍停留在“正在分析…”状态的问题。

## 修复内容

- Android 流式响应改用 Okio `ResponseBody.source()` 逐行读取 SSE，减少附件长流尾部读取异常。
- FDEX `type=done` 事件现在作为确定完成信号，客户端收到后立即结束当前流，不再依赖额外 `[DONE]` 或连接 EOF。
- 已收到正文或媒体后，即使反向代理丢失最后的 `[DONE]`，正常 EOF 仍按成功完成处理。
- 第一段真实正文或媒体到达 Android 时立即清除旧的“正在分析…”状态。
- 非音频附件的 SSE 空闲超时调整为 30 秒。FDEX 服务端正常附件流程会每 5–12 秒发送状态心跳；如果客户端到服务端的流异常中断，会更快进入既有非流式兼容回退，而不是长时间卡死。
- 流式请求和兼容回退继续共用同一个请求 ID，方便通过 `FDEX_AI` 日志串联诊断。
- 增加 SSE 行拆包 JVM 回归测试，覆盖正文数据、显式 done、`[DONE]`、前导空格和非 data 行。

## 本次现场依据

真实设备请求已经在 FDEX 服务端出现 `provider_first_content`、`provider_attempt_success` 与 `stream_done`，且 chat2api 后台请求为 completed、扩展页面可看到正确图片理解答案，因此本次问题明确位于 Android 下游 SSE 消费/收尾，而非供应商或视觉模型生成失败。
