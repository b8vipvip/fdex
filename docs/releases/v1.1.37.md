# FDEX v1.1.37 Release Notes / FDEX v1.1.37 正式版说明

Release baseline / 发布基线：`main@62ba3f98b2ee268861822a6b9cf27f873e20b022`

This release packages all accepted changes since `v1.1.36` into the next signed Android production release. / 本次发布将 `v1.1.36` 之后已经验收通过的全部改动纳入下一版 Android 正式签名发行版。

## Major changes / 主要改动

- Universal 智体 model parity across server/Web flows and Coding Agent integration.
- Official OpenAI Codex app-server based Coding Agent runtime, durable Thread/Turn/Item lifecycle, approvals, requestUserInput and MCP elicitation.
- Owner-scoped Remote MCP registry, credential vault, OAuth/PKCE, process-tree resource isolation and Codex Runtime lifecycle controls.
- Codex Provider fresh-full compatibility seal, structured Agent health monitoring and fail-closed readiness.
- Agent-first Coding Agent routing and Codex-only execution core; no Legacy/Auto Agent engine and no fallback to ordinary `client_ai` for Coding-Agent-enabled 智体.
- Structured bounded retry with logical task projection, atomic retry lineage and durable retry-transition crash reconciliation.
- Retry journal/account erasure consistency and account-operation fencing around the first durable AgentTask write.
- GitHub authority remains owned by FDEX: Codex does not receive GitHub Installation tokens and does not directly push or open PRs.

## Accepted architecture / 已验收架构

Current accepted Coding Agent architecture is **Phase 7.43 — Account Operation / Agent Task Creation Fence**. Phase 7.41–7.43 final PR heads and merged-main CI have all passed FastAPI tests, Android unit tests and Android Debug APK builds.

## Release process / 发布流程

The release PR title intentionally contains `[release]`. After the PR is merged and its `Build and Test` workflow succeeds on `main`, `.github/workflows/auto-tag-release.yml` will automatically:

1. resolve the next patch version from the latest semver tag (`v1.1.36` -> `v1.1.37`);
2. create and push tag `v1.1.37` at that accepted main commit;
3. validate Android signing secrets;
4. build the signed release APK with `VERSION_NAME=1.1.37`;
5. upload the signed APK artifact;
6. create the GitHub Release and attach `fdex-1.1.37.apk`.

No release is considered complete until the tag, GitHub Release and signed APK asset are all verified.
