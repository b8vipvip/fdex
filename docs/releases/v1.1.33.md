# FDEX v1.1.33

本版本把 Coding Agent 的 GitHub 项目接入从 Android 手工粘贴 Token 改为账号级 GitHub Device OAuth，并补齐授权令牌轮换、仓库发现和跨账号隔离。

## Android GitHub 授权

- Android 不再显示或提交 GitHub Token 输入框。
- 用户点击“连接 GitHub”后，FDEX 服务端创建 Device Flow；Android 复制一次性用户码并打开 GitHub 官方确认页。
- 客户端按服务端返回的重试时间自动检查授权状态，不超过 GitHub 要求的轮询频率。
- 授权完成后只列出该 GitHub 身份有权访问的仓库，可搜索并自动读取默认分支。
- 仓库没有 push 权限时按只读项目保存；有写权限时才允许 Agent push 自己的 `fdex-agent/*` 分支和创建 PR。

## 服务端安全边界

- Device Flow、GitHub connection 和 repository discovery 全部绑定当前 FDEX `user_id`；另一账号无法读取或轮询。
- `device_code`、access token 和 refresh token 使用现有 Agent Fernet key 加密保存，API 响应与账号数据导出均不包含密钥或密文。
- 服务端使用 SQLite `BEGIN IMMEDIATE` 串行化 Device Flow 轮询，并在响应中给出安全的 `retry_after_seconds`。
- 对启用 expiring tokens 的 GitHub App/OAuth App，服务端在跨 worker 文件锁内轮换 access/refresh token，并重新读取 `/user` 校验 GitHub user id，防止令牌轮换串号。
- 账号注销同时删除 Device Flow、GitHub connection、Agent project、持久化任务和账号沙箱。

## 管理与兼容

- Coding Agent 管理页新增 GitHub OAuth Client ID 和 scope 配置，并说明 GitHub App 侧必须启用 Device Flow。
- `.env.example` 新增 `FDEX_GITHUB_OAUTH_CLIENT_ID`、`FDEX_GITHUB_OAUTH_SCOPE` 与刷新提前量。
- Device Flow 不需要把 GitHub Client Secret 部署到 FDEX 或 Android。
- 原 PAT Connector 保留为旧部署迁移/管理员应急入口，新版 Android 不再调用。

## 验证

- FastAPI 全量测试覆盖设备码加密、owner scope、轮询 cadence、授权成功、access/refresh token 轮换、GitHub identity 复核、仓库安全字段裁剪和旧数据库迁移。
- Android 单元结构测试确保两个 Coding Agent 项目入口统一使用 Device OAuth，且客户端源码不再构造 GitHub token payload。
- Android unit tests、Debug APK 与 FastAPI Tests 由 GitHub Actions 在合并前统一验证。
