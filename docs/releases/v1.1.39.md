# FDEX v1.1.39

Production release that binds Codex Provider compatibility evidence to the actual upstream chat2api runtime contract.

## Included

- FDEX now discovers the chat2api `/version` contract and derives a secret-free upstream runtime identity from the Server Runtime, Worker bundle/build revision, and route authority revisions.
- Codex Provider full-smoke fingerprints include that upstream identity. A chat2api Server/Worker deployment therefore invalidates smoke evidence created against the previous runtime even when Base URL, API Key and model configuration are unchanged.
- The 60-second Codex Agent health monitor refreshes the upstream contract before compatibility evaluation, so an upstream deployment becomes `FINGERPRINT_MISMATCH` in the same monitor cycle rather than remaining trusted for the previous 168-hour maximum age.
- Real Provider smoke records the detected upstream contract before issuing fresh compatibility evidence.
- Compatibility persistence stores only the hashed upstream identity and public version metadata; Provider API keys are not persisted in the contract record.
- Adds regression coverage for chat2api runtime/Worker contract rotation and stale full-smoke invalidation.

## Cross-project release target

This release is intended to pair with chat2api `v0.22.75` / Worker `0.8.31`, including route-close terminal reporter revision 91. After chat2api is upgraded, FDEX will require a new real full-smoke before the Provider is eligible for production rollout.

## Release path

The merge commit must contain `[release]`. After merged-main `Build and Test` succeeds, `auto-tag-release.yml` will resolve the next patch tag (`v1.1.39`), build the signed Android APK, and publish the GitHub Release asset.
