# FDEX v1.1.19

本版本把 Realtime 实时语音正式接入 FDEX 的 MemPalace 原始历史与 Letta 结构化长期记忆。记忆数据只使用已经由实时协议转成文字、并在 FDEX 聊天界面回显的内容，不保存语音 PCM、Base64 音频或其他音频格式。

## Realtime 长期记忆

- Android Realtime `start` 帧新增独立 `memory_control`，包含不透明账户 scope 与员工 ACL；该字段只由 FDEX 服务端消费，不会转发给 GPT-Live / OpenAI Realtime 上游。
- 新 Realtime 会话连接上游模型前，服务端按员工聊天读取权限加载最近 MemPalace 原始历史。
- 员工 `knowledgeRead=true` 时，同时召回 Letta 结构化长期记忆。
- 召回结果与员工角色 Prompt 组合进当前 Realtime 会话的 system/instructions，实现跨会话长期记忆。
- 当前实时通话内部继续由同一个 GPT-Live / Realtime 会话维持本次上下文，不切换供应商、模型或普通 HTTP AI 路径。

## 纯文本写入

- `user_transcript` / `transcript.final` 作为用户文字。
- `assistant_transcript` / `response.text.delta` 作为 AI 回复文字。
- 完成的一问一答异步写入 MemPalace；员工 `knowledgeWrite=true` 时同时更新 Letta。
- 被打断但已经产生文字回显的 AI 部分回复同样按当前聊天界面实际可见文本保存，并避免 `interrupt + done` 重复写入。
- Realtime 输入框发送的文字仍通过当前 WebSocket 的 `input.text` / `conversation.item.create` 进入同一个实时模型会话；长期记忆写入前会剥离 FDEX 内部候选资料，只保存用户可见文字。
- 音频数据只参与实时传输与播放，长期记忆模块没有音频写入入口。

## MemPalace 启动召回

- 新增按账户 scope 和员工 ACL 读取 recent verbatim drawer 的路径。
- Realtime 建连时尚未产生本轮用户问题，因此 recent 读取直接从 MemPalace SQLite 获取最近获准历史，不依赖 embedding / Qdrant 查询，降低语音会话启动依赖。
- Letta 结构化记忆与 recent MemPalace 可并行、fail-open 召回；记忆组件异常不会迫使实时语音切换模型或供应商。

## chat2api GPT-Live 协议边界

已核对 `chat2api-live-v1`：当前协议支持 `session.start`、`input_text` / `conversation.item.create`、barge-in/打断和结束，但没有定义会话中途更新 instructions/system 的控制事件。因此 FDEX 不伪造 `session.update`。跨会话长期记忆在建立新 Realtime 会话前装载；本次通话中新产生的上下文由同一个实时会话自身维护，完成后的纯文本记忆供后续新会话继续召回。
