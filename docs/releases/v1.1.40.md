# FDEX v1.1.40

Production release adding server-side request records and per-request diagnostic log export to the FDEX administration console.

## Included

- Adds a new **请求记录** entry to the server administration sidebar at `/admin/requests`.
- Records all public `/api` requests with a stable `X-FDEX-Request-ID`, request method/path, status, elapsed time, client metadata and event count.
- Keeps richer internal event chains for AI requests, including provider attempts and related request diagnostics already emitted by the existing trace layer.
- Adds filtering by request method, request state, keyword and result limit.
- Adds per-request `.log` export containing the request summary and complete ordered diagnostic event chain.
- Persists request diagnostics in bounded SQLite WAL storage with a 30-day / 20,000-request retention policy.
- Does not store request or response bodies and re-redacts obvious tokens, cookies, passwords, API keys and other secrets before persistence.
- Keeps request logging fail-open so diagnostics storage failures do not interrupt normal API traffic.
- Includes automated coverage for storage aggregation, redaction, API-wide tracing, administration listing and single-request export.

## Validation

The feature PR passed the complete `Build and Test` workflow before merge, including FastAPI tests, Android unit tests, Debug APK build and artifact upload.
