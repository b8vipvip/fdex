# FDEX v1.1.17

本版本集中修复员工聊天发送图片、文件等附件时可能长时间停留在“正在准备附件并连接 AI”的链路问题，并补齐服务端可复制的附件/流式请求诊断日志。

## 主要修复

### 附件上传与流式连接

- Android AI HTTP 请求改用 OkHttp，并为连接、附件上传写入和流式读取分别设置可控超时。
- 附件上传不再依赖缺少写超时的旧 `HttpURLConnection` 路径，避免网络异常时数分钟无反馈。
- 客户端显示更明确的阶段状态：读取附件、生成请求数据、上传 FDEX、服务端解析、供应商连接、等待上游响应。
- 同一次流式请求和兼容回退共用同一个请求 ID，失败提示可直接关联服务端日志。

### 图片上传体积优化

- 大于 1 MB 的普通视觉图片在 Android 本机按最长边 1600 px 采样/缩放，并以适合视觉分析的 JPEG 发送。
- 避免手机拍照原图经 Base64 后进一步膨胀，显著降低图片任务的上传等待和代理层压力。
- 普通文档继续保持原始文件字节，不改变文档正文内容。

### 服务端 SSE 与附件解析

- 文档正文提取不再阻塞在 `StreamingResponse` 创建之前。
- 文档解析放到工作线程执行，并在耗时期间周期性发送状态心跳。
- 普通文本/视觉供应商连接增加等待响应头和等待 SSE 输出的心跳，避免客户端长期只看到一个静态状态。
- 回答正文已经开始后仍保持原有安全策略：上游中断时终止当前回答，不切换供应商造成重复正文。

### 服务端诊断日志

新增一行一个事件的 `FDEX_AI {...}` 结构化运行日志，包含：

- `request_id`
- HTTP 请求进入/响应状态
- 请求体 Content-Length
- 图片、音频、文档数量和编码后大小
- 文档解析开始/结束/耗时
- AI 路由结果
- 供应商与模型尝试
- 等待响应头、等待 SSE 输出的心跳
- 上游 HTTP 状态
- 首个流式事件与首段正文
- 异常类型和失败原因

日志不会写入 API Key、文件正文、Prompt 正文或图片/文件 Base64。

### 宝塔 / Nginx

- 部署模板增加 `proxy_request_buffering off;`，让大附件请求不必先由 Nginx 完整缓存后才转给 FastAPI。
- 增加 `client_body_timeout 120s;`，避免异常上传无限拖延。

## 日志排查

服务端更新后，可以在宝塔服务日志或 systemd 日志中搜索 `FDEX_AI`。同一次客户端请求会携带相同 `request_id`，可判断问题处于客户端/Nginx 上传、FastAPI 请求体解析、文档提取、供应商连接、上游响应头还是 SSE 输出阶段。
