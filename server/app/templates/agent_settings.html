隔离与权限边界

account → project → task 三层文件隔离 + FDEX GitHub 权限控制 + Codex workspace sandbox

账号 / 项目隔离

不同账号使用不同 owner/CODEX_HOME/GitHub 凭据；不同项目不共用 repository/worktree。Codex 只收到当前任务 worktree。

密钥隔离

Codex 子进程经过 FDEX 环境清洗；GitHub/SMTP/Admin 等服务密钥不会继承，模型 API Key 仅供 Codex Runtime 调用上游，shell 工具环境明确不继承它。

GitHub 写权限

Codex 被明确禁止直接 push/PR。只有任务结束后，FDEX 根据项目 allow_push/allow_pr 决定是否使用账号自己的 GitHub App 权限推送 fdex-agent/* 分支。

交互式权限

原生协议已经接收审批、权限请求、MCP elicitation、用户输入等 server request；FDEX 的 owner/project policy 仍是上限，用户审批不能越过宿主安全边界。

保护路径

Codex 结果在提交前再次扫描；若触碰 .env、server/data 或 .git 内部路径，FDEX 会阻止 commit/push。
